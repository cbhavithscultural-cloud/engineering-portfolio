02 / AUTONOMOUS ROBOTICS · SIMULATION

Adaptive mobile robot in ROS 2 and Gazebo.

A simulation environment for exploring differential-drive motion, LiDAR-based reactive obstacle avoidance and planar state estimation. The work separates simulated behaviour from claims about a physical robot.

ROS 2 HumbleGazebo ClassicLiDAR /scanrobot_localizationEKFPython

01 / Simulation model

The robot is represented as a differential-drive platform in Gazebo Classic with a 360-ray LiDAR and an IMU sensor plugin. The simulated drive configuration uses a 0.34 m wheel separation and 0.14 m wheel diameter.

02 / Reactive obstacle avoidance

A ROS 2 node consumes /scan and publishes velocity commands to /cmd_vel. It examines front, left and right angular sectors, uses a low-percentile range estimate for obstacle clearance, and chooses forward motion or a turn based on configured distance thresholds. Missing or stale scan data leads to a stop rather than an assumed clear path.

03 / State estimation

The robot_localization EKF is configured in two-dimensional mode at 30 Hz. It fuses planar position, yaw and selected velocity terms from wheel odometry with gyro-Z from /imu/data. This is a limited planar fusion configuration, not full six-axis inertial navigation.

04 / Logging and evaluation

ROS topics and Gazebo model states are logged for later comparison of ground-truth motion, wheel odometry and filtered odometry. The logger outputs CSV data for plotting and inspection. Reproducible evaluation requires the simulation environment and dependencies to be installed.

05 / Current limitations

This is a Gazebo simulation, not a validated physical navigation stack. The obstacle-avoidance logic is reactive rather than global path planning; EKF quality depends on sensor and odometry configuration; and the package should be rebuilt and tested in the target ROS environment before claiming a clean reproducible installation.
